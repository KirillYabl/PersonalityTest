# Структура

```text
.
├── app/
│   ├── api/
│   │   ├── some_route/
│   │   │   ├── v1/
│   │   │   │   └── api.py    # эндпоинты и роутер
│   │   │   │   └── schema.py # схемы входных данных
│   └── router.py    # все роутеры
│   ├── commands/    # команды, запускающиеся отдельно от основного сервера
│   ├── core/        # базовая функциональность и настройки
│   └── .env    # секретные переменные
│   ├── db/          # вся работа с БД
│   │   ├── tables/          # описаняи моделей
│   │   ├── repositories/    # репозитории над моделяеми, вся выборка данных через них
│   ├── migrations/  # миграции БД
│   ├── resources/   # константы
│   ├── schemas/     # схемы данных
│   ├── selects/     # простые выборки данных (при переходе на специфичные репозитории все переносится в них)
│   ├── services/    # бизнес логика
│   ├── static/      # статические файлы (здесь для tg mini app)
│   ├── templates/   # шаблоны html страниц  (здесь для tg mini app)
│   ├── tests/       # тесты
│   ├── utils/       # мелкая вспомогательная функциональность
└── docker-compose.yaml
```

# Особенности

## Ошибки в api

Все ошибки отдающиеся наружу имеет свой уникальный внутренний код ошибки, для этого они наследуются от ServiceException.

Также ошибки накапливаются в групповой ошибке ServiceExceptionGroup.

Сервисы накапливают эти ошибки и выкидывает в API и в сервере для отлова ошибки такого класса заведен хэндлер обработчик.

## Сервисы

Вся бизнес логика, все то, что используют API ручки или какие-то фоновые задачи, инкапсулируются в сервисах.

Сервисы устроены по некоему аналогу Dependency Injection, они в себе хранят все зависимости и при необходимости зависимости могут легко меняться.

Струткура сервиса:

```python
@dataclass(frozen=True, kw_only=True, slots=True)
class Service:
    _private_dependebcy = dependency_fabric
    _other_private_dependency = other_dependency_fabric

    async def __call__(self, service_args, service_kwarg=service_kwarg) -> something:
        ...

service = Service()
```

Использование frozen, kw_only и slots делает стиль написания кода близким к функциональному, избегая путаницы с состояниями.

Другие функции внутри сервиса можно не писать, они пишутся за классом и передаются в сервис как зависимости.

Потом может получится что схожая функция нужно внутри сервиса и она переносится в selects.

То, что все зависимости (внешние функции, которые он будет вызывать, репозитории, соединения и тд) задаются при ициализации
сервиса, позволяет их очень легко тестировать, не требуя сложных моков.

## Репозитории

Вся работы с выбоками и изменениями данных ведется в репозиториях.

Репозиторий это способ работы с объектом какого-то типа (с одной таблицей) в специальной технологии.

В текущем состоянии используется глупые репозитории, которые умеют делать только бызовые операции с
таблицами и ничего не знают про структуру БД, а вся логика зашивается в seelcts и services.

Но в дальнейшем лучше перейти на умные репозитории, которые будут хорошо знать структуру БД.

## Аутентификация

Все ручки кроме статики спрятаны под JWT.

Получение JWT для каждого способа свое, реализовано для пользователей телеграм.

При загрузке mini app, он отправляет данные, которые сверяются с токеном бота
телеграма и тогда по id пользователя в телеграм получается юзер (или автоматически создается
новый), по его uuid шифруется новый токен и отправляется.

Таким образом аутентификация сейчас для любого пользователя данного mini app.

Для подключения других способов аутентификации, например для веба с регистрацией пользователя,
нужно будет реализовывать свои способы получения токена, а дальше уже пользоваться им универсально в остальных ручках.

## Команды

Все команды над инфраструктурным слоям хранятся в папке `commands`.

Для команд есть интерфейс `Command`, который поддерживает прямой и обратный запуск.

Новая команда пишется как наследник интерфейса и в файле с командой происходит также ее вызов через `.run_cli` метод.

Если нужно передавать какие-то параметры, то делается это через инициализацию команды.

Все команды запускаются так:
```shell
uv run -m commands.my_command [--unrun]
```
